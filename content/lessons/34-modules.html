ماژول‌ها: import و export

پروژه‌ی بزرگ را نمی‌شود در یک فایل نوشت. ماژول‌ها اجازه می‌دهند کد را به فایل‌های کوچک و مرتب بشکنی، هر فایل فقط چیزی را که لازم است نشان بدهد و بقیه‌ی فایل‌ها فقط همان را بردارند. این درس پایه‌ی کار با فریم‌ورک‌ها (React، Vue و ...) و ابزارهایی مثل Vite است.

چرا ماژول؟

بدون ماژول، همه‌ی فایل‌ها با تگ‌های script پشت سر هم بارگیری می‌شوند و همه‌ی متغیرها در یک فضای مشترک (global) قرار می‌گیرند. دو فایل ممکن است ناخواسته یک اسم را بازنویسی کنند و ترتیب نوشتن تگ‌ها هم مهم می‌شود. ماژول‌ها این سه مشکل را حل می‌کنند:

  • فضای جدا: هر فایل متغیرهای خودش را دارد و چیزی بیرون نمی‌رود مگر با export.
  • وابستگی روشن: بالای هر فایل نوشته شده از کجا چه چیزی می‌خواهد.
  • بارگیری مرتب: مرورگر خودش فایل‌ها را به ترتیب وابستگی می‌آورد.
۲

export و import

با export چیزی را از یک فایل بیرون می‌دهی و با import در فایل دیگر می‌گیری. دو نوع export داریم: نام‌دار (named، هر تعداد) و پیش‌فرض (default، فقط یکی در هر فایل).

فایل‌های ماژولjs
// math.js
export const PI = 3.14159;
export function area(r) { return PI * r * r; }
export const double = (n) => n * 2;

// logger.js
export default function log(msg) {          // export پیش‌فرض
  console.log("[LOG]", msg);
}
استفادهjs
// main.js
import log from "./logger.js";                 // پیش‌فرض: هر اسمی بگذاری
import { PI, area } from "./math.js";          // نام‌دار: اسم باید یکی باشد
import { double as twice } from "./math.js";   // تغییر نام با as

log(area(2));       // 12.56636
log(twice(21));     // 42
مراقب باش

در مسیر import پسوند .js و شروع با ./ (یا ../) را فراموش نکن. بدون آن مرورگر فکر می‌کند اسم یک بسته‌ی نصب‌شده است و خطا می‌دهد.

۳

استفاده در HTML

برای اینکه مرورگر فایل را به‌عنوان ماژول بخواند، تگ را با type="module" می‌نویسی. فقط فایل ورودی (main) را در HTML می‌گذاری؛ بقیه را خودش import می‌کند.

index.htmlhtml
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<body>
  <h1 id="title"></h1>
  <script type="module" src="main.js"></script>
</body>
</html>
  • اسکریپت ماژول به‌طور خودکار defer است؛ بعد از ساخته شدن صفحه اجرا می‌شود، پس لازم نیست DOMContentLoaded بنویسی.
  • همیشه در حالت strict است.
  • متغیرها به window نمی‌چسبند؛ onclick="..." داخل HTML نمی‌تواند به آن‌ها دسترسی بگیرد و باید با addEventListener وصل کنی.
مراقب باش: Live Server

ماژول‌ها با باز کردن مستقیم فایل (file://) خطای CORS می‌دهند. حتماً پروژه را با یک سرور محلی اجرا کن؛ ساده‌ترین راه افزونه‌ی Live Server در VS Code است.

ترکیب و وارد کردن پویا

چند الگوی دیگر که در پروژه‌های واقعی زیاد می‌بینی:

الگوهای پیشرفتهjs
// وارد کردن همه با یک نام (namespace)
import * as utils from "./utils.js";
utils.format(10);

// بازصادرکردن: یک فایل «ورودی» که چند ماژول را جمع می‌کند (index.js)
export { area, PI } from "./math.js";
export { default as log } from "./logger.js";

// import پویا: فقط وقتی لازم شد بارگیری شود (سرعت بیشتر)
button.addEventListener("click", async () => {
  const { drawChart } = await import("./chart.js");
  drawChart();
});
بدان

import پویا (import()) یک Promise برمی‌گرداند، پس با await یا .then استفاده می‌شود. برای بخش‌های سنگین سایت که همیشه لازم نیست عالی است.

ساختار پیشنهادی پروژه

نمونه‌ی ساختارtxt
my-app/
├── index.html
├── style.css
└── js/
    ├── main.js        ← نقطه‌ی شروع (type="module")
    ├── api.js         ← کار با fetch
    ├── storage.js     ← localStorage
    ├── ui.js          ← ساخت و تغییر DOM
    └── utils.js       ← توابع کمکی کوچک

هر فایل یک مسئولیت دارد. اگر پروژه‌ی تودولیست را اینطور بشکنی، storage.js را بدون دست زدن به بقیه عوض می‌کنی (مثلاً به یک API واقعی) و این همان چیزی است که به آن کد تمیز می‌گویند.

تمرین‌ها

تمرین ۱

پروژه‌ی «ماشین حساب» را به سه فایل بشکن: calc.js (فقط محاسبه‌ها)، ui.js (نمایش) و main.js.

راهنمایی

توابع calc و clean را با export بیرون بده و در main.js import کن. حتماً با Live Server اجرا کن.

تمرین ۲

یک فایل index.js بساز که export * from چند فایل را جمع کند و بقیه فقط از همان import کنند.

راهنماییexport * from "./a.js"; همه‌ی exportهای نام‌دار را بازصادر می‌کند (default را نه).
