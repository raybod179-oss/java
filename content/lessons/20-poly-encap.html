۱

Polymorphism: یک نام، چند رفتار

کلاس‌های مختلف متدی با یک نام دارند ولی هرکدام کار خودش را می‌کند. کد بیرونی بدون نگرانی از نوع واقعی آبجکت فقط متد را صدا می‌زند.

کد · قابل اجراjs
class Payment { pay(amount) { return "پرداخت"; } }
class Card extends Payment {
  pay(amount) { return `کارت بانکی: ${amount}`; }
}
class Wallet extends Payment {
  pay(amount) { return `کیف پول: ${amount}`; }
}
const methods = [new Card(), new Wallet()];
methods.forEach((m) => console.log(m.pay(50000)));

اگر فردا روش پرداخت سوم اضافه شود، کد چرخه‌ی بالا هیچ تغییری نمی‌کند. این قدرت اصلی Polymorphism است.

۲

Encapsulation: مخفی کردن جزئیات

فیلدهایی که با # شروع می‌شوند خصوصی‌اند و فقط داخل کلاس دیده می‌شوند. بقیه‌ی برنامه فقط از متدهای مجاز استفاده می‌کند.

کد · قابل اجراjs
class BankAccount {
  #balance = 0;                     // خصوصی
  deposit(n) {
    if (n <= 0) throw new Error("مبلغ نامعتبر");
    this.#balance += n;
  }
  withdraw(n) {
    if (n > this.#balance) throw new Error("موجودی کافی نیست");
    this.#balance -= n;
  }
  get balance() { return this.#balance; }
}
const acc = new BankAccount();
acc.deposit(100);
acc.withdraw(30);
console.log(acc.balance);
console.log(acc.balance = 99999, acc.balance);   // قابل تغییر از بیرون نیست
try { acc.withdraw(1000); } catch (e) { console.log("خطا:", e.message); }
فایده

بدون Encapsulation هر جای برنامه می‌توانست balance را مستقیم عوض کند و پیدا کردن باگ سخت می‌شد. حالا همه‌ی تغییرات از یک مسیر کنترل‌شده می‌گذرند.

دیدن پاسخ
کد · قابل اجراjs
class Wallet {
  #money = 0;
  add(n) { this.#money += n; return this; }
  get money() { return this.#money; }
}
console.log(new Wallet().add(5).add(7).money);
