۱

پورتفولیو چیست و چه چیزی باید داشته باشد؟

پورتفولیو یک صفحه‌ی وب است که کارهایت را نشان می‌دهد. کارفرما معمولاً چند دقیقه وقت دارد؛ پس کمتر ولی بهتر:

  • ۴ تا ۶ پروژه‌ی خوب به‌جای ۲۰ پروژه‌ی نیمه‌کاره.
  • برای هر پروژه: عکس یا GIF، یک جمله درباره‌ی مسئله‌ای که حل می‌کند، تکنولوژی‌ها، لینک نسخه‌ی زنده و لینک کد.
  • یک بخش «درباره‌ی من» کوتاه و راه ارتباطی (ایمیل، تلگرام، GitHub، لینکدین).
  • سایتی که روی موبایل هم درست دیده شود.
۲

کدام پروژه‌ها را انتخاب کنم؟

پروژه‌های دوره برای یادگیری‌اند؛ برای پورتفولیو باید «مال خودت» شوند. پیشنهاد انتخاب از میان پروژه‌های دوره:

  • فروشگاه با سبد خرید (نشان‌دهنده‌ی مدیریت state و ذخیره‌سازی)
  • برنامه‌ی آب‌وهوا یا Movie API (نشان‌دهنده‌ی کار با API و مدیریت خطا)
  • تودولیست با LocalStorage (CRUD کامل)
  • سایت تک‌صفحه‌ای (طراحی و انیمیشن)
  • یک پروژه‌ی ایده‌ی خودت که در دوره نبوده
صادق بمان

سورس پروژه‌ها را می‌توانی شخصی‌سازی کنی، ولی همان نسخه‌ی بدون تغییر را به‌عنوان «کار خودم» نگذار. حداقل چند ویژگی از بخش «چالش‌ها» را اضافه کن، ظاهر را عوض کن و اسم و محتوای خودت را بگذار. مصاحبه‌کننده معمولاً می‌پرسد «این بخش را چطور نوشتی؟».

۳

GitHub: اولین مخزن

Git سیستم نگه‌داری نسخه‌های کد است و GitHub سایتی که مخزن‌های Git را نگه می‌دارد. بعد از نصب Git و ساخت حساب، در پوشه‌ی پروژه:

دستورهای پایه‌ی Gitsh
git init                              # شروع مخزن در این پوشه
git add .                             # همه‌ی فایل‌ها را برای ثبت آماده کن
git commit -m "اولین نسخه‌ی پروژه"    # یک نقطه‌ی ذخیره بساز
git branch -M main
git remote add origin https://github.com/نام-کاربری/نام-مخزن.git
git push -u origin main               # بفرست به GitHub

بعد از آن، هر تغییر مهم را با git add . و git commit -m "..." و git push ثبت کن. پیام‌های commit را کوتاه و روشن بنویس: «افزودن فیلتر دسته»، نه «تغییر».

۴

کسی که مخزن تو را باز می‌کند اول README را می‌بیند. یک قالب ساده که همیشه کار می‌کند:

نمونه README.mdmd
# فروشگاه کوچک (JavaScript)

سبد خرید کامل با ذخیره در LocalStorage.

🔗 **نسخه‌ی زنده:** https://example.netlify.app

۵

انتشار آنلاین

پروژه‌ی تو فقط HTML و CSS و JavaScript است، پس همه‌ی این روش‌ها رایگان و ساده‌اند:

  1. Netlify: وارد سایت شو و پوشه‌ی پروژه را بکش و رها کن (Netlify Drop) یا مخزن GitHub را وصل کن تا با هر push خودکار منتشر شود.
  2. GitHub Pages: در مخزن به Settings ← Pages برو و شاخه‌ی main را انتخاب کن.
  3. Vercel: مخزن را import کن؛ برای سایت ساده‌ی استاتیک تنظیمی لازم نیست.
قبل از انتشار

بعد از انتشار، لینک را از روی گوشی هم باز کن و ببین درست دیده می‌شود. همچنین مطمئن شو در کدت کلید API یا رمزی نمانده؛ هرچه در GitHub عمومی باشد، همه می‌بینند.

رزومه، لینکدین و چک‌لیست

  • رزومه‌ی یک صفحه‌ای: چکیده‌ی دو خطی، مهارت‌ها (JavaScript، DOM، API، Git)، ۳ تا ۴ پروژه با لینک، تحصیلات و دوره‌ها.
  • پروفایل لینکدین یا پروفایل کاری: عکس واضح، عنوان روشن («توسعه‌دهنده‌ی فرانت‌اند»)، لینک پورتفولیو.
  • مخزن GitHub مرتب: README برای هر پروژه، پین کردن ۴ پروژه‌ی برتر، پروفایل کامل.
واقع‌بینی
