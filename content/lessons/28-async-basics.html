ناهمزمانی و Event Loop

جاوااسکریپت تک‌نخی است: در هر لحظه فقط یک کار انجام می‌دهد. پس اگر یک درخواست به سرور ۳ ثانیه طول بکشد و همه‌چیز منتظرش بماند، صفحه قفل می‌شود. راه‌حل، کدهای ناهمزمان است: کار طولانی را شروع می‌کنی، ادامه‌ی برنامه اجرا می‌شود و وقتی نتیجه آماده شد، تابعی که تعیین کرده‌ای اجرا می‌شود.

توی این درس چه چیزهایی یاد می‌گیریم؟

  1. اول همزمان‌ها، بعد صف
  2. Microtask در برابر Macrotask
  3. Callback و جهنم Callback
  4. تمرین‌ها
۱

اول همزمان‌ها، بعد صف

کد · قابل اجراjs
console.log("1) شروع");
setTimeout(() => console.log("3) بعد از تایمر"), 0);
console.log("2) پایان کد همزمان");

با اینکه تأخیر صفر است، تایمر آخر اجرا شد. دلیلش Event Loop است: کدهای معمولی در Call Stack اجرا می‌شوند. تایمرها و درخواست‌ها به مرورگر سپرده می‌شوند و وقتی تمام شدند، تابعشان در صف می‌ایستد. Event Loop فقط وقتی Call Stack کاملاً خالی شد، از صف کار برمی‌دارد.

۲

Microtask در برابر Macrotask

دو صف داریم. صف Promise (Microtask) اولویت بالاتری دارد و قبل از صف تایمرها (Macrotask) خالی می‌شود.

کد · قابل اجراjs
console.log("A: همزمان");
setTimeout(() => console.log("D: setTimeout"), 0);
Promise.resolve().then(() => console.log("C: Promise"));
console.log("B: همزمان");
نکته

ترتیب خروجی همیشه A، B، C، D است. این سوال را در مصاحبه‌های کاری زیاد می‌پرسند.

۳

Callback و جهنم Callback

قدیمی‌ترین راه، دادن یک تابع به تابع دیگر است تا بعد از پایان کار صدا زده شود. وقتی چند کار پشت‌سرهم لازم باشد، کد به شکل هرم تو در تو در می‌آید.

کد · قابل اجراjs
function step(name, next) {
  setTimeout(() => { console.log(name); next(); }, 300);
}
step("۱) ورود", () => {
  step("۲) دریافت اطلاعات", () => {
    step("۳) نمایش", () => console.log("تمام"));
  });
});

بخش‌های بعد با Promise و async/await این هرم را به کدی صاف و خواندنی تبدیل می‌کنند.

تمرین ۲

چالش: تابع delayedHello(name, ms) بنویس که بعد از ms میلی‌ثانیه «سلام name» را چاپ کند

دیدن پاسخ
کد · قابل اجراjs
function delayedHello(name, ms) {
  setTimeout(() => console.log("سلام " + name), ms);
}
delayedHello("Rayvo", 500);
