شروع فریلنسری و قیمت‌گذاری پروژه

بعد از یادگیری، می‌توانی کار کردن را از پروژه‌های کوچک شروع کنی. این درس یک راه‌نمای عملی و صادقانه است: از پیدا کردن اولین مشتری تا برآورد زمان و قیمت، قرارداد ساده و ارتباط با مشتری. (این درس مشاوره‌ی حقوقی یا مالی نیست؛ برای قراردادهای مهم از متخصص کمک بگیر.)

۱

واقع‌بینی

اولین پروژه‌ی پولی معمولاً از آشنایان، شبکه‌ی ارتباطی یا یک نمونه‌کار خوب می‌آید، نه از پیام سرد. انتظار نداشته باش در هفته‌ی اول مشتری گران پیدا شود. هدف سه ماه اول: دو تا سه پروژه‌ی کوچک، رضایت مشتری و نمونه‌کار واقعی.

۲

چه خدماتی می‌توانم بفروشم؟

با آنچه در این دوره ساخته‌ای، این خدمات قابل ارائه‌اند:

  • سایت معرفی تک‌صفحه‌ای برای کسب‌وکار کوچک (ریسپانسیو، فرم تماس، سئوی پایه)
  • رفع باگ و بهبود جاوااسکریپت سایت‌های موجود
  • ابزارهای کوچک وب: ماشین حساب، فرم ثبت‌نام، لیست و فیلتر
  • افزودن اسلایدر، منوی موبایل، مودال و انیمیشن به سایت‌های آماده
  • اتصال سایت به یک API (نمایش داده‌های بیرونی)
اعتبار اول

از خدماتی شروع کن که برای تو قابل تحویل مطمئن است. وعده‌ی فروشگاه کامل با پرداخت آنلاین قبل از تسلط نده؛ اعتبارت از هر پروژه‌ی بزرگ مهم‌تر است.

۳

برآورد زمان و قیمت

قیمت‌گذاری از «ساعت» شروع می‌شود، نه از حدس. روش ساده:

  1. پروژه را به کارهای کوچک بشکن (صفحه‌ی اصلی، فرم، ریسپانسیو، تست، تحویل).
  2. برای هر کار ساعت واقعی‌ات را بنویس و خوش‌بینی را کنار بگذار؛ معمولاً بیشتر طول می‌کشد.
  3. جمع ساعت‌ها را در نرخ ساعتی ضرب کن، بعد برای ریسک و تغییرات درصد اضافه کن.
  4. عدد را با بازار مقایسه کن (پروژه‌های مشابه، پرسیدن از هم‌صنفی‌ها) و گرد کن.
کد · قابل اجراjs
// عددها فرضی‌اند؛ نرخ واقعی را با بازار و تجربه‌ی خودت تعیین کن
function estimate({ hours, rate, risk = 0.2, buffer = 0.15 }) {
  const base = hours * rate;                   // هزینه‌ی ساعت‌ها
  const total = base * (1 + risk + buffer);    // ریسک و تغییرات
  return Math.round(total / 1000) * 1000;
}
console.log(estimate({ hours: 30, rate: 300000 }).toLocaleString("fa-IR"), "تومان");
تله‌ی قیمت پایین

قیمت را نه خیلی پایین بگذار (کار با کیفیت کم و تو خسته) نه خیلی بالا. و هیچ‌وقت «بدون قرارداد و پیش‌پرداخت» کار بزرگ شروع نکن.

۴

قرارداد و پرداخت ساده

قرارداد لازم نیست پیچیده باشد؛ ولی این‌ها باید نوشته شوند (حتی در یک پیام تأییدشده):

  • محدوده: دقیقاً چه چیزی ساخته می‌شود و چه چیزی نه (مثلاً «سه صفحه» و «بدون پنل مدیریت»)
  • زمان تحویل و تعداد دفعات اصلاح رایگان
  • پرداخت مرحله‌ای: پیش‌پرداخت قبل از شروع، بخش میانی، باقی‌مانده هنگام تحویل
  • تغییرات جدید: هرچه خارج از محدوده باشد، جدا برآورد و پرداخت می‌شود
  • مالکیت: بعد از پرداخت کامل، کد به مشتری منتقل می‌شود
۵

ارتباط با مشتری

بیشتر اختلاف‌ها از ارتباط بد می‌آید، نه از کد بد. عادت‌های خوب:

  • اول سؤال بپرس: هدف سایت، مخاطب، نمونه‌های دلخواه، محتوا (متن و عکس) را چه کسی می‌دهد؟
  • پیشرفت را هفته‌ای یک‌بار نشان بده (لینک آزمایشی).
  • همه‌ی توافق‌ها را مکتوب کن.
  • اگر عقب افتادی، زود و صادقانه بگو.
نمونه‌ی پیام اول به مشتریtxt
سلام، ممنون از پیام شما.
برای اینکه دقیق برآورد کنم، چند سؤال دارم:
۱) هدف اصلی سایت چیست (معرفی، فروش، جذب مشتری)؟
۲) چند صفحه می‌خواهید و متن و عکس‌ها آماده است؟
۳) نمونه‌ی سایتی که از ظاهرش خوشتان می‌آید؟
۴) زمان دلخواه تحویل؟
بعد از پاسخ، ظرف ۲۴ ساعت برآورد زمان و هزینه را می‌فرستم.

  • نگرفتن نمونه‌ی ظاهر و محتوا از قبل
  • تحویل بدون تست روی موبایل و مرورگرهای دیگر
  • قیمت‌گذاری با حدس و بدون شکستن کار به بخش‌ها
