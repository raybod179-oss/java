انواع خطا و خواندن پیام

هر خطا یک name (نوع)، یک message (توضیح) و یک stack (ردپای فراخوانی‌ها) دارد. نوع خطا نیمی از راه‌حل را می‌گوید:

کد · قابل اجراjs
const tests = [
  ["TypeError", () => null.name],                  // خواندن از null یا undefined
  ["ReferenceError", () => undefinedVariable],     // متغیر وجود ندارد
  ["SyntaxError", () => JSON.parse("{bad json}")], // نوشتار اشتباه
  ["RangeError", () => new Array(-1)],             // عدد خارج از بازه
];
for (const [expected, fn] of tests) {
  try { fn(); } catch (e) { console.log(expected, "←", e.name); }
}
بدان

پیام «Cannot read properties of undefined (reading "x")» رایج‌ترین خطای جاوااسکریپت است: یعنی چیزی که انتظار آبجکت داشتی undefined بود. اول ببین آن مقدار از کجا می‌آید (API هنوز نیامده؟ اسم کلید غلط است؟).

try، catch و finally

بخش finally همیشه اجرا می‌شود، چه خطا رخ دهد چه نه. برای کارهای پایانی مثل خاموش کردن loading عالی است.

کد · قابل اجراjs
function readSettings(text) {
  try {
    console.log("۱) شروع");
    const data = JSON.parse(text);
    console.log("۲) خوانده شد:", data.theme);
    return data;
  } catch (e) {
    console.log("۳) خطا:", e.name);
    return { theme: "light" };                 // مقدار پیش‌فرض امن
  } finally {
    console.log("۴) همیشه اجرا می‌شود");
  }
}
readSettings('{"theme":"dark"}');
readSettings("خراب");
کد · قابل اجراjs
// ?. و ?? جلوی بسیاری از TypeError ها را می‌گیرند
const user = { profile: null };
console.log(user.profile?.city);               // undefined (بدون خطا)
console.log(user.profile?.city ?? "نامشخص");   // نامشخص

ساختن و پرتاب خطای دلخواه

با throw خودت خطا پرتاب می‌کنی و با class ... extends Error نوع جدید می‌سازی. به این شکل در catch می‌فهمی با کدام نوع خطا طرفی و فقط خطاهایی را که می‌شناسی مدیریت می‌کنی.

کد · قابل اجراjs
class ValidationError extends Error {
  constructor(field, message) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

function validate(user) {
  if (!user.email) throw new ValidationError("email", "ایمیل لازم است");
  return true;
}

try {
  validate({});
} catch (e) {
  if (e instanceof ValidationError) console.log("فیلد:", e.field, "|", e.message);
  else throw e;                    // خطای ناشناخته را قورت نده؛ دوباره پرتاب کن
}
مراقب باش

هرگز یک catch خالی ننویس. خطایی که بی‌صدا قورت داده شود، روزها بعد به شکل یک باگ مرموز برمی‌گردد. دست‌کم آن را در کنسول چاپ کن.

۴

خطا در کدهای ناهمزمان

در async/await همان try/catch کار می‌کند. با .then/.catch هم می‌توان گرفت. چیزی که هیچ‌کس نگیرد، unhandled rejection می‌شود.

کد · قابل اجراjs
async function load() { throw new Error("سرور جواب نداد"); }

async function main() {
  try {
    await load();
  } catch (e) {
    console.log("گرفته شد:", e.message);
  }
}
main();
load().catch((e) => console.log("با catch هم می‌شود:", e.message));
تور ایمنی سراسریjs
// تور ایمنی سراسری: خطاهایی که هیچ‌جا گرفته نشدند
window.addEventListener("error", (e) => {
  console.error("خطای کلی:", e.message, e.filename, e.lineno);
  // اینجا می‌توانی خطا را به یک سرویس گزارش‌دهی بفرستی
});
window.addEventListener("unhandledrejection", (e) => {
  console.error("Promise گرفته‌نشده:", e.reason);
});

ابزارهای دیباگ مرورگر

با F12 (یا کلیک راست ← Inspect) ابزارهای توسعه‌دهنده باز می‌شوند. این تب‌ها را باید بشناسی:

  • Console: خطاها و خروجی console.log. روی نام فایل و شماره‌ی خط خطا کلیک کن تا به همان خط بروی.
  • Sources: روی شماره‌ی یک خط کلیک کن تا نقطه‌ی توقف (breakpoint) بگذاری؛ اجرا همان‌جا می‌ایستد و مقدار همه‌ی متغیرها را می‌بینی. با F10 خط‌به‌خط جلو برو.
  • Network: همه‌ی درخواست‌ها، وضعیت (۲۰۰، ۴۰۴، ...)، زمان و محتوای جواب. برای پروژه‌ی API، اولین جایی که باید نگاه کنی.
  • Application: محتوای localStorage و کوکی‌ها.
متدهای کنسول (در کنسول مرورگر امتحان کن)js
console.log("ساده");
console.error("خطا (قرمز)");
console.warn("هشدار (زرد)");
console.table([{ name: "علی", age: 25 }, { name: "سارا", age: 30 }]);   // جدول
console.group("گروه");
console.log("داخل گروه");
console.groupEnd();
console.time("حلقه");
for (let i = 0; i < 1e6; i++) {}
console.timeEnd("حلقه");        // زمان اجرا
debugger;                        // اگر DevTools باز باشد، اینجا می‌ایستد

روش حل باگ

بیشتر باگ‌ها را با یک روش ثابت می‌شود حل کرد:

  1. خطا را بخوان: نوع، پیام و شماره‌ی خط.
  2. تکرارش کن: دقیقاً چه کاری باعث خطا می‌شود؟
  3. مشکوک را محدود کن: با console.log یا breakpoint ببین کجا مقدار از انتظارت جدا می‌شود.
  4. یک چیز را عوض کن: هر بار فقط یک تغییر، تا بدانی چه چیز مشکل را حل کرد.
  5. تست کن و پاکسازی: لاگ‌ها را بردار و مطمئن شو چیز دیگری خراب نشده.
ترفند «اردک لاستیکی»

اگر بیشتر از ۳۰ دقیقه گیر کردی، مشکل را به‌صورت یک جمله بنویس (دقیقاً چه انتظاری داشتی و چه شد). نوشتن خودش اغلب جواب را نشان می‌دهد؛ اگر نشد، همین جمله را در پشتیبانی بپرس.

تمرین‌ها

تمرین ۱

تابعی بنویس که یک رشته‌ی JSON بگیرد و در صورت خراب بودن، بدون خطا یک آبجکت خالی برگرداند.

پاسخ
کد · قابل اجراjs
const safeParse = (text) => { try { return JSON.parse(text); } catch (e) { return {}; } };
console.log(safeParse('{"a":1}'), safeParse("خراب"));
تمرین ۲

کلاس NotFoundError بساز که یک status = 404 داشته باشد و در catch با instanceof تشخیصش بده.

پاسخ
کد · قابل اجراjs
class NotFoundError extends Error {
  constructor(what) { super(what + " پیدا نشد"); this.name = "NotFoundError"; this.status = 404; }
}
try { throw new NotFoundError("کاربر"); }
catch (e) { console.log(e instanceof NotFoundError, e.status, e.message); }
